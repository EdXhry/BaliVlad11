# Исправления планировщика и логики дайджеста — 1 августа 2026

## Проблемы
1. Бот не публиковал дайджест в запланированное время (05:00 МСК)
2. Дайджест показывал предстоящие события вместо недавно опубликованных

## Корневая причина #1: Планировщик
Функция `_reload_jobs()` вызывалась каждую минуту и **пересоздавала задачи планировщика** с помощью `add_job(..., replace_existing=True)`. Это сбрасывало таймер задачи на следующий день. Задача никогда не доживала до своего времени срабатывания.

## Корневая причина #2: Логика дайджеста
Функция `compile_digest()` использовала `get_upcoming_events()` которая показывала события **на 7 дней вперёд** (по дате мероприятия), а не **добавленные за последние 7 дней** (по дате парсинга).

## Исправления

### 1. main.py — Кеширование настроек планировщика
Добавлен словарь `_last_schedule` для хранения последних загруженных настроек. Теперь `_reload_jobs()` проверяет изменились ли настройки перед вызовом `add_job()`. Задачи пересоздаются **только если настройки реально изменились**.

### 2. scheduler_settings.py — Упрощённая работа с timezone
Добавлена поддержка упрощённых офсетов вида `UTC+3`, `UTC+8` и т.д. Это проще и работает на любой ОС.

### 3. storage.py — Новая функция get_recently_added_events()
Добавлена функция которая возвращает события **по дате добавления в базу** (поле `created_at`), а не по дате мероприятия.

**Логика:**
- Берёт все события где `created_at` за последние 7 дней
- Сортирует по дате мероприятия (для красивого отображения)
- Возвращает список

### 4. digest.py — Использование новой функции
Заменён `storage.get_upcoming_events()` на `storage.get_recently_added_events()`.

**Было:**
```python
events = storage.get_upcoming_events(days=7)  # события на 7 дней вперёд
```

**Стало:**
```python
events = storage.get_recently_added_events(days=7)  # добавленные за 7 дней
```

### 5. data/settings.json — Настройка на МСК
Установлено расписание по московскому времени:
- `"timezone": "UTC+3"` (МСК)
- `"collect_time": "04:40"` (за 20 минут до публикации)
- `"digest_time": "05:00"` (5 утра по МСК = 10 утра на Бали)

## Результат
✅ Задачи планировщика создаются один раз при старте  
✅ Пересоздаются только при изменении настроек через admin-бот  
✅ Расписание работает на любой ОС (Windows/Linux)  
✅ Сбор данных в **04:40 МСК (01:40 UTC)** каждый день  
✅ Публикация дайджеста в **05:00 МСК (02:00 UTC)** каждый день  
✅ Разрыв между сбором и публикацией: **20 минут**  
✅ Дайджест показывает **новые события за последние 7 дней** (по дате парсинга)

## Логика работы

### Сбор (04:40 МСК)
1. Парсит все источники (Telegram + сайты)
2. Фильтрует по теме, гео, языку
3. Сохраняет новые события с `created_at = текущее время UTC`
4. Дубликаты отбрасываются

### Публикация (05:00 МСК)
1. Запрашивает события где `created_at` за последние 7 дней
2. Формирует дайджест в два блока (оффлайн Бали + онлайн RU)
3. Публикует в Telegram
4. Удаляет события старше 30 дней

## Временны́е зоны
- 05:00 МСК (Москва, UTC+3)
- 10:00 WITA (Бали, UTC+8)
- 02:00 UTC (серверное время)

## Как проверить
1. Запустить бота: `python main.py`
2. В логах должна быть строка:
   ```
   Планировщик: сбор 04:40 UTC+3 → 01:40 UTC (каждый день)
   Планировщик: дайджест 05:00 UTC+3 → 02:00 UTC (каждый день)
   ```
3. Дальнейшие минутные проверки `_reload_jobs` НЕ должны логировать "Обновление расписания"
4. В 05:00 МСК (02:00 UTC) должна произойти публикация с заголовком "Новое за 7 дней"

## Важно
После деплоя новой версии бот нужно **перезапустить**. Старая версия продолжит пересоздавать задачи каждую минуту.
